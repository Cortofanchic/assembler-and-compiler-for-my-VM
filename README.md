# Ассемблер Учебной Виртуальной Машины (УВМ) — Вариант 26

CLI-ассемблер для Учебной Виртуальной Машины (УВМ). Программа транслирует исходный код на языке ассемблера в промежуточное представление (IR), а затем кодирует его в бинарный машинный код (формат `little-endian`, размер машинного слова — 3 байта).

## Система команд УВМ (Вариант 26)

Каждая инструкция занимает **3 байта (24 бита)** и имеет поля `A` (код операции) и опциональное поле `B` (операнд: константа или адрес памяти).

| Операция | Код (`A`) | Операнд (`B`) | Синтаксис | Семантика | Пример |
| :--- | :---: | :---: | :--- | :--- | :--- |
| Загрузка константы | `6` | Константа | `acc = <число>` | Загрузить константу `B` в аккумулятор | `acc = 827` |
| Чтение из памяти | `0` | — | `acc = mem[acc]` | Загрузить в аккумулятор значение из памяти по адресу в `acc` | `acc = mem[acc]` |
| Запись в память | `5` | Адрес | `mem[<адрес>] = acc` | Записать значение аккумулятора в память по адресу `B` | `mem[314] = acc` |
| Логический сдвиг вправо | `7` | Адрес | `acc = acc >> mem[<адрес>]` | Сдвинуть `acc` вправо на значение из памяти по адресу `B` | `acc = acc >> mem[162]` |

### Синтаксические возможности парсера (`parser.py`)
* **Комментарии:** поддерживаются строчные комментарии через `;` и `//`.
* **Форматы чисел:** десятичные (`827`), шестнадцатеричные (`0x33B`), двоичные и восьмеричные.
* **Метки:** поддерживается объявление меток (`loop:`) и обращение к ним по имени или через префикс (`@loop`). Метки автоматически резолвятся в байтовые адреса.
* **Гибкий синтаксис операндов:** допускается запись как через пробел (`LOAD_CONST 827`), так и через знак равенства (`LOAD_CONST = 827`).

## Архитектура и основные функции

### 1. CLI-интерфейс (`asm.py`)
* `main(argv)` — обрабатывает аргументы командной строки (`source`, `output`, `--test`), управляет чтением/записью файлов и кодами возврата (`0` — успех, `1` — провал тестов, `2` — ошибка чтения, `3` — ошибка ассемблирования, `4` — ошибка записи).
* `_load_commands(text)` — запускает парсинг исходного текста и вычисляет байтовые смещения (`byte_addr`) для каждой инструкции.
* `run_spec_tests()` — встроенный набор контрольных тестов из спецификации для самопроверки кодировщика.
* `_print_test_output(commands, binary)` — выводит промежуточное представление (поля `A` и `B`) и результирующие байты в шестнадцатеричном формате (`0xDE, 0x19, 0x00`).

### 2. Парсер (`vm_asm/parser.py`)
* `parse(source)` — выполняет двухпроходный разбор текста программы:
  1. `_collect_labels()` — очищает комментарии, регистрирует метки и связывает их с байтовыми адресами.
  2. `_parse_line()` — валидирует мнемоники, проверяет количество операндов и переводит их в целочисленные значения с проверкой разрядности поля `B` (`_resolve()`).
* `Command` — структура данных промежуточного представления (IR), хранящая мнемонику, значения полей, номер строки и адрес.

### 3. Кодировщик (`vm_asm/encoder.py`)
* `_encode_word(command)` — упаковывает код операции `A` и операнд `B` в 24-битное целое число с помощью побитовых сдвигов и масок.
* `encode(commands)` — преобразует список команд IR в последовательность байтов в формате `little-endian`.

## Запуск программы

### Требования
* Python 3.8 или выше (используется только стандартная библиотека, сторонние зависимости не требуются).

### Обычная компиляция в бинарный файл
```bash
python asm.py <путь_к_исходнику.asm> <путь_к_выходному_файлу.bin>
```
Пример:
```bash
python asm.py tests/demo.asm build/demo.bin
```

### Запуск в режиме тестирования (`--test`)
Флаг `--test` выводит промежуточное представление (значения полей `A` и `B`), сгенерированные байты каждой команды и запускает встроенную таблицу контрольных тестов:
```bash
python asm.py tests/spec_load.asm build/spec_load.bin --test
```

Пример вывода:
```text
Test (A=6, B=827):
0xDE, 0x19, 0x00
```

## Запуск тестов

Для автоматического прогона всех тестовых файлов из спецификации (`spec_*.asm`) и демонстрационной программы (`demo.asm`):

1. Перейдите в директорию `tests`:
   ```bash
   cd tests
   ```
2. Запустите тестовый раннер:
   ```bash
   python run_tests.py
   ```
Скрипт автоматически создаст директорию `tests/tests_results/`, скомпилирует все `.asm` файлы в `.bin` и выведет результат трансляции для каждого теста.

Для тестирования работы самого АВМ на тестах из спецификации используйте
```bash
   python tests/test_vm.py
   ```

Для тестирования работы интерпретатора АВМ на тестах из спецификации используйте
```bash
   python tests/test_intepr.py
   ```

Быстрый запуск осуществляется через `run.bat` и `run_intepr.bat`.
